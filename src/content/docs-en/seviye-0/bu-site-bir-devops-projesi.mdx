## Why dogfooding?

Eating your own dog food — using your own product. This repo serves two purposes at once:

1. **A textbook:** it teaches DevOps interactively.
2. **A live guinea pig:** every tool you learn gets applied to this very site.

In Level 2 you'll write its real CI pipeline; in Level 3 you'll turn it into a Docker image and run it on Kubernetes; in Level 4 you'll monitor it; in Level 5 you'll ship it end-to-end to production. No concept stays floating on “some other example project”.

## Why Astro is a good choice here

Astro is a **web framework** designed for content-driven sites. Three features matter for this repo:

1. **Content Collections:** every `.mdx` file under `src/content/docs/` is **validated at build time** against the schema in `content.config.ts`. If a lesson says `level: 7`, the build **fails** — content quality is itself a CI check.
2. **Islands Architecture:** interactive pieces (quiz, terminal simulator) load JavaScript only when needed; static text stays pure HTML. Result: a fast site.
3. **Static output:** `npm run build` produces pure HTML/CSS/JS — the simplest, cheapest and safest hosting format. Deployment lessons lean on this.

<Callout type="info" title="Schema = contract">
  The content schema is a contract: every lesson's title, level, duration and
  objectives are guaranteed by the schema. This is the content-world cousin of
  Infrastructure as Code — configuration isn't separate from code, it's a
  validated part of it.
</Callout>

If you want to see it on the command line, from the repo root:

```bash
npm install    # install dependencies (once)
npm run dev    # dev server (localhost:4321)
npm run build  # produce the static site into dist/
```

## The site's transformation across levels

| Level | What you'll add to the site |
| --- | --- |
| 1 | Its Git-versioned form; managing changes via branches/PRs |
| 2 | GitHub Actions for automatic test + build + deploy |
| 3 | A Dockerfile, image registry, deploy to a local Kubernetes cluster |
| 4 | Uptime monitoring, log/metric collection |
| 5 | A GitOps flow, canary/blue-green deploy scenario |

Being both the **writer** and the **runner** of one project — that's the essence of DevOps.
