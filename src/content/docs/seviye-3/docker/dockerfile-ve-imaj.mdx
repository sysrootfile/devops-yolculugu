## Hedef

Bu sitenin kendisini bir Docker imajına dönüştüreceğiz — içinde **nginx** ile servis edilecek statik dosyalar. Bu Dockerfile, sonraki derslerde Kubernetes'e taşınacak imajın ta kendisi.

## Dockerfile'ı yazalım

Repo köküne `Dockerfile`:

```dockerfile
# 1. Aşama: siteyi derle (builder)
FROM node:22-alpine AS builder
WORKDIR /app

# bağımlılık tanımlarını önce kopyala (katman cache'i için!)
COPY package.json package-lock.json ./
RUN npm ci

# kaynak kodu kopyala ve derle
COPY . .
RUN npm run build

# 2. Aşama: yalnızca üretilen dosyaları taşı (minimal çalışma imajı)
FROM nginx:1.27-alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
```

Satır satır anlatalım:

| Direktif | Ne yapar? | Neden böyle? |
| --- | --- | --- |
| `FROM ... AS builder` | Derleme ortamı (multi-stage — bir sonraki ders) | Node sadece derlemek için gerekli, servise gerek yok |
| `WORKDIR /app` | Sonraki komutların dizini | Mutlak yol kirliliğini önler |
| `COPY package*.json ./` | Önce manifest'ler | Kod her değiştiğinde `npm ci` katmanı **cache'ten** gelir |
| `RUN npm ci` | Bağımlılık kurulumu | Lockfile'a sadık (Seviye 2 kuralı) |
| `COPY . .` | Kaynak kod | Sık değişen şey en sonda |
| `COPY --from=builder` | Ürünü yeni imaja taşı | node_modules (400MB+) son imaja taşınmaz! |

Gördüğün desen: **npm ci'dan sonra gelen her adım, npm ci ile birlikte cache'ten düşer.** Bu yüzden manifest'ler önce kopyalanır.

<Callout type="info" title="Gerçek dünyadan: taban imaj seçimi bir boyut stratejisidir">
  Aynı Node uygulaması; Debian tabanlı bir imajda, `slim` varyantında ve
  `alpine` tabanında kat kat farklı boyutlara sahiptir — ve “distroless” hareketi,
  yalnızca runtime'ın gerçekte ihtiyaç duyduğu dosyaları bırakarak boyutu ve
  saldırı yüzeyini minimuma indirir. Katman sırası (bu derste yaptığın cache
  provası) build hızını; taban seçimi ise pull süresini ve güvenlik yükünü belirler.
  İkisi birlikte imaj hijyeninin iki ayağıdır.
</Callout>

## Çalıştır ve doğrula

```bash
docker build -t devops-site:1.0.0 .
docker run --rm -p 8080:80 devops-site:1.0.0
# tarayıcı: http://localhost:8080  → site çalışıyor!
```

Faydalı kontrol komutları:

```bash
docker images                          # imajlar + boyutlar
docker ps                              # çalışan container'lar
docker exec -it <id> sh                # container içine gir (Alpine'da bash yok, sh var)
curl -I http://localhost:8080          # HTTP 200 görmelisin
```

<Callout type="info" title="Neden nginx?">
  Astro statik dosya üretir; bunu servis etmenin en hafif yolu nginx (ya da caddy)
  gibidir. Node + Express ile “statik dosya servis etmeye” çalışmak yerine uzman aracı
  kullanmak — Unix felsefesinin devamı (Seviye 1: her araç tek işi iyi yapar).
</Callout>

  id="s3-dockerfile-lab"
  title="İmajını üret"
  verify={['docker images | grep devops-site', 'curl -I http://localhost:8080 | head -1']}
>
  1. Docker Desktop (Windows/Mac) veya Docker Engine kurulu olmalı: `docker version`.
  2. **Önce bu dersten Dockerfile'ı kendi yazdığın versiyonla oluştur**, sonra repodaki `Dockerfile` ve `.dockerignore` ile karşılaştır (repo'daki dosya referans implementasyondur — kopyalamak yerine farkları bulmak daha öğretici!).
  3. `docker build -t devops-site:1.0.0 .`
  4. `docker run --rm -p 8080:80 devops-site:1.0.0` → tarayıcıda kontrol et.
  5. Bir derse bir satır ekle, yeniden build al: `npm ci` katmanının **CACHED** olduğunu izle.
  6. Bonus: repoda bu imaj artık CI tarafından GHCR'a da gönderiliyor (Seviye 3'ün *Registry ve Multi-stage* dersindeki desen) — Actions sekmesinde `docker` job'ını incele.
</LabBox>
