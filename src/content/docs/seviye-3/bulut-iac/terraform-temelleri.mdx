## Infrastructure as Code: “sunucu kurmak” = “PR açmak”

Konsoldan tıklayarak kurulan altyapının üç problemi vardır: **tekrarlanamaz** (yeni ortam = yeniden tıklama), **izlenebilir değildir** (kim ne değiştirdi?), **kalıcı değildir** (bilgi bir kişinin hafızasında). IaC bunları çözer: altyapı, kod gibi yazılır → review edilir → versiyonlanır → otomatik uygulanır.

**Terraform** bu işin standart aracıdır: HCL diliyle yazarsın, *hangi bulut olursa olsun* (AWS, Azure, GCP, Cloudflare... — provider'lar) aynı workflow'u kullanır.

## Workflow: init → plan → apply

```hcl
# main.tf — bir statik site bucket'ı (vendor-neutral örnek: AWS)
terraform {
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 5.0" }
  }
}

provider "aws" {
  region = "eu-central-1"
}

resource "aws_s3_bucket" "site" {
  bucket = "devops-yolculugu-prod"
}

resource "aws_s3_bucket_public_access_block" "site" {
  bucket                  = aws_s3_bucket.site.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}
```

```bash
terraform init    # provider'ları indir (npm install karşılığı)
terraform plan    # NE DEĞİŞECEK? (dry run — asla atlanmaz)
terraform apply   # plan onaylandıktan sonra uygula
```

`plan` çıktısının dili:

```
  + create   # eklenecek kaynak
  ~ update   # değiştirilecek (in-place)
  - destroy  # silinecek — OKUYUP ANLAMADAN onay verme!
  -/+ replace # sil-yeniden oluştur (downtime riski!)
```

## State: Terraform'un hafızası

Terraform, "ne kurduğunu" **state dosyasında** (`terraform.tfstate`) tutar. Bu dosya:

- Gerçek kaynaklarla kod arasındaki **köprüdür**
- **Şifreli ve paylaşımlı** olmalıdır (S3 + DynamoDB lock gibi **remote backend**'lerde tutulur)
- **Repoya commit EDİLMEZ** — içinde secret'lar olabilir, ve ekip tek state üzerinden çalışmalıdır

```hcl
terraform {
  backend "s3" {
    bucket         = "tf-state-benim"
    key            = "prod/site.tfstate"
    region         = "eu-central-1"
    dynamodb_table = "tf-locks"
  }
}
```

Lock mekanizması kritiktir: iki kişi aynı anda `apply` ederse state bozulur; lock bunu önler.

## Modüller: yeniden kullanılabilir altyapı

Terraform kodu da fonksiyonlara bölünür — **module**:

```hcl
module "static_site" {
  source      = "./modules/static-site"
  domain      = "site.example.com"
  environment = "prod"
}
```

Aynı modülü dev/staging/prod için farklı değerlerle çağırırsın — IaC'nin DRY'ı.

## DevOps bağlantısı: plan, CI'da çalışır

İyi pratik: **PR'da `terraform plan` çıktısı otomatik yorum olarak düşer** (CI). Review eden kişi, altyapının ne değişeceğini kodla birlikte görür. `apply` ise yalnızca merge sonrası, korumalı pipeline'dan geçer — altyapı değişikliği de bir deployment disiplinine tabidir.

<Callout type="info" title="📦 Kurulum: Terraform">
  Doğrula: `terraform --version`. Kurulum: Windows `winget install Hashicorp.Terraform`
  · macOS `brew tap hashicorp/tap && brew install hashicorp/tap/hashicorp/terraform`
  · Linux resmî apt deposu: **Araç Kurulum Rehberi**.
</Callout>

<LabBox
  id="s3-terraform-lab"
  title="İlk terraform döngün"
  verify={['terraform --version', 'terraform fmt -check || terraform fmt']}
>
  1. `terraform` CLI'ını kur (hashicorp.com/install).
  2. Boş klasörde yukarıdaki `main.tf`'yi yaz (provider'ı lokal çalıştırılabilir bir şey yapabilirsin — ör. `local_file` provider'ı ücretsiz ve anında çalışır!).
  3. `terraform init && terraform plan` — çıktıyı **okuyarak** geç.
  4. `terraform apply -auto-approve` ile uygula; oluşan dosyayı kontrol et.
  5. Koddaki bir etiketi değiştir → `plan` (update görmelisin) → `apply`.
  6. `terraform destroy` ile temizle.
  7. Bonus: `terraform fmt` — kod formatını otomatikleştirir (CI'da `-check` ile doğrulanır).
</LabBox>

<Callout type="tip" title="Lokal provider ile risk almadan öğren">
  Gerçek bulut hesabı olmadan Terraform öğrenmek için `local_file` (dosya yaratır),
  `null` (hiçbir şey yapmayan) provider’ları idealdir: plan/apply/state döngüsünün
  tamamını risk almadan yaşarsın. Bulut hesabına geçiş sadece `provider` bloğu
  değiştirmektir.
</Callout>
