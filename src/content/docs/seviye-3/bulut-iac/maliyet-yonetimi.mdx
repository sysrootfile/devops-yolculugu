## Bulutun paradoksu

“Kullandığın kadar öde” vaadi iki yüzlüdür: başlangıç maliyeti sıfıra iner ama **kontrol edilmezse her şey ücretli bir faaliyettir**. Klasik fatura şoku kaynakları:

1. **Unutulan kaynaklar:** test için açılan VM (haftalarca açık), hata ayıklama VM'i
2. **Veri transferi:** bölge dışı çıkış trafiği (egress) sessiz ama pahalıdır
3. **Yanlış boyut (overprovisioning):** 7/24 %5 CPU ile çalışan 8 vCPU VM
4. **Snapshot/log birikimi:** silinen VM'in arkasında kalan diskler ve yedekler
5. **Yönetilmeyen cache/queue:** mesaj birikimi, eski deployment artıkları

## Kontrol katmanları

### 1. Etiketleme (tagging) politikası

Her kaynakta standart etiketler: `project`, `environment`, `owner`. IaC ile zorunlu kılınır:

```hcl
locals {
  common_tags = {
    project     = "devops-yolculugu"
    environment = var.environment
    owner       = "ekip-a"
  }
}
resource "aws_instance" "test" {
  # ...
  tags = local.common_tags
}
```

Etiketsiz kaynak = **sahipsiz fatura satırı**. Maliyet raporlarını etikete göre kırarsın; kim ne harcıyor sorusunun tek cevabı budur.

### 2. Bütçe ve alarm

Her bulutta bütçe takibi var (AWS Budgets, Azure Cost Management, GCP Budgets). Kural: **proje açılır açılmaz bütçe + e-posta alarmı kurulur** — “%50'sini geçince haber ver, %90'da beni ara” gibi. Terraform ile bunu da koda yazarsın; alarm kurulumu unutulmaz.

### 3. Kullandığını kapat: kısa ömürlü ortamlar

PR bazlı test ortamı, merge sonrası **otomatik yıkılır**:

```bash
terraform apply -var-file=env/pr.tfvars   # PR açılınca (CI)
terraform destroy -var-file=env/pr.tfvars # merge/silinince (CI)
```

Geliştirme ortamı gece kapanır sabah açılır (scheduler) — %60+ tasarruf klasik sonuçtur. IaC'nin gücü: *yıkıp kurmak artık acı değil, rutin.*

### 4. Doğru boyut ve doğru model

- **Spot/Preemptible VM:** en ucuz kapasite (pahalı: aniden kesilebilir) — batch işler, CI runner, test ortamları için ideal
- **Reserved/Savings Plans:** kesintisiz 7/24 iş yükü için 1-3 yıl taahhüt
- **Serverless:** boşta maliyeti sıfır — seyrek tetiklenen işler için
- **Managed servis tekrar kontrolü:** RDS mi, kendi EC2'de Postgres mi? Operasyon maliyeti + güvenlik dahil hesaplanır

### 5. Sürekli bakım

```bash
# “orphans” avı — aylık rutin
# - etiketsiz kaynaklar
# - unattached disk/snapshot
# - eski imaj/artifact (registry temizliği)
# - idle load balancer
```

Bulut hesabının çöp odası düzenli temizlenir; IaC dışından elle yaratılan kaynaklar bu bakımda öncelikli şüphelidir (drift detection: `terraform plan` beklenmeyen farkları gösterir).

<Callout type="tip" title="FinOps refleksi">
  FinOps = bulut maliyetini de bir ürün metriği gibi yönetmek: görünür kıl (etiket+rapor),
  hedefle (bütçe), optimize et (doğru boyut/spot/kısa ömürlü ortam), döngüye al.
  DevOps mühendisinin fatura okuma becerisi, incident müdahale becerisi kadar değerlidir.
</Callout>
