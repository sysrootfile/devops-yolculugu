## Neden “dogfooding”?

Eating your own dog food — yani kendi ürününü kendin kullanmak. Bu repo iki görevi aynı anda görür:

1. **Ders kitabı:** DevOps’u interaktif şekilde öğretir.
2. **Canlı denek tavşanı:** Öğrendiğin her aracı, bu sitenin kendisine uygularsın.

Seviye 2’de bu repoya gerçek bir CI pipeline’ı yazacaksın; Seviye 3’te siteyi Docker imajına dönüştürecek, Kubernetes’e koyacaksın; Seviye 4’te monitoring’e alacaksın; Seviye 5’te uçtan uca production’a taşıyacaksın. Böylece hiçbir kavram “başka bir örnek proje”de havada kalmaz.

## Astro'nun burada iyi bir seçim olmasının nedenleri

Astro bir **web framework’ü**; “content-driven” siteler için tasarlanmış. Bu repo için üç özelliği kritik:

1. **Content Collections:** `src/content/docs/` altındaki her `.mdx` dosyası, `content.config.ts`’te tanımlı şemayla **build zamanında doğrulanır**. Bir derste `level: 7` yazarsan build **başarısız olur** — yani içerik kalitesi bile bir CI kontrolüdür.
2. **Islands Architecture:** Quiz, terminal simülatörü gibi interaktif parçalar yalnızca gerektiğinde JavaScript yükler; statik metin saf HTML kalır. Sonuç: hızlı site.
3. **Statik çıktı:** `npm run build` komutu saf HTML/CSS/JS üretir — hosting’i en basit, en ucuz ve en güvenli formatta. Deployment derslerinde bu özelliği bol bol kullanacağız.

<Callout type="info" title="Şema = sözleşme">
  İçerik şeması bir “sözleşmedir”: her dersin başlığı, seviyesi, süresi ve hedefleri şemayla
  garanti edilir. Bu, Infrastructure as Code fikrinin içerik dünyasındaki karşılığıdır —
  yapılandırma koddan ayrı değil, doğrulanabilir bir parçasıdır.
</Callout>

Komut satırında görmek istersen, bu reponun kökünde:

```bash
npm install    # bağımlılıkları kur (bir kez)
npm run dev    # geliştirme sunucusu (localhost:4321)
npm run build  # statik siteyi dist/ klasörüne üret
```

## Bu sitenin ilerleyen seviyelerdeki dönüşümü

| Seviye | Siteye yapacağın ekleme |
| --- | --- |
| 1 | Git ile versiyonlanmış hali; değişiklikleri branch/PR ile yönetme |
| 2 | GitHub Actions ile otomatik lint + build + deploy |
| 3 | Dockerfile, imaj registry, lokal Kubernetes kümesine deploy |
| 4 | Uptime monitoring, log/metric toplama |
| 5 | GitOps akışı, canary/blue-green deploy senaryosu |

Tek bir projede hem **yazan** hem **çalıştıran** tarafı deneyimlemek — DevOps’un özü tam olarak budur.
