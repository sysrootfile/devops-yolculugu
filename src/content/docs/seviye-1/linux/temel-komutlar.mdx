## Terminal neden DevOps’un ana aracı?

Sunuculara genellikle **SSH ile bağlanırsın** — grafik arayüz yok. Betikler (scripts) yazarsın — terminal komutları bunların yapı taşları. CI pipeline’ları da aslında terminal komutları çalıştırır. Yani terminali akıcı kullanmak, DevOps’un “okuma yazma” becerisidir.

## Gezinme ve dosya yönetimi

| Komut | Yapar | Örnek |
| --- | --- | --- |
| `pwd` | Bulunduğun dizini yazar | `pwd` |
| `ls` | Listeler | `ls -la` (gizli dosyalar + detay) |
| `cd` | Dizin değiştirir | `cd /var/log`, `cd ..` |
| `mkdir` | Dizin oluşturur | `mkdir -p app/logs` |
| `touch` | Boş dosya oluşturur | `touch not.txt` |
| `cp` / `mv` | Kopyalar / taşır-yeniden adlandırır | `mv eski.txt yeni.txt` |
| `rm` | Siler | `rm -r klasor/` (dikkat!) |
| `cat` / `less` | Dosya içeriği | `cat /etc/hostname` |

<Callout type="danger" title="Altın kural">
  `rm` için geri dönüşüm kutusu yoktur. `rm -rf` kullanacaksan komutu çalıştırmadan
  önce **yolu bir kez daha oku**. Özellikle `sudo` ile birleşince sistem-kirici güçte olur.
</Callout>

## Pipe: komutları zincirleme

Unix felsefesi: *her araç tek işi iyi yapsın, araçlar birleşsin.* Pipe (`|`) bir komutun çıktısını diğerinin girdisine bağlar:

```bash
# app.log içindeki ERROR satırlarını bul, kaç tane olduğunu say
grep ERROR app.log | wc -l

# En çok bellek kullanan 3 süreci listele
ps aux | sort -k4 -rn | head -3

# journaldaki nginx loglarında "500" geçen satırların son 5'i
journalctl -u nginx | grep 500 | tail -5
```

Okuma alışkanlığı: soldan sağa, çıktı→girdi. `grep ... | wc -l` = “ele, sonra say.”

## Arama: find ve grep farkı

- **`find`** → **dosya/dizin** arar (isim, boyut, tarih)
- **`grep`** → **dosyanın içindeki** metni arar

```bash
# Adı "conf" içeren dosyaları /etc altında ara
find /etc -name "*conf*" 2>/dev/null

# 10MB'tan büyük dosyaları bul
find / -size +10M 2>/dev/null

# src klasöründe "TODO" geçen satırlar (dosya adlarıyla)
grep -rn "TODO" src/
```

`2>/dev/null` = hata mesajlarını (izin verilmedi dizinleri) bastır. `grep -r` rekürsif, `-n` satır numarası.

## Diğer günlük silahlar

```bash
chmod +x deploy.sh        # script'e çalıştırma izni ver (bir sonraki derste derinleşecek)
history | tail -20        # son komutların
df -h                     # disk kullanımı
free -h                   # bellek
top                       # canlı süreç/bellek paneli (çıkış: q)
which python3             # bir komutun hangi dosyada olduğu
man grep                  # el kitabı (çıkış: q) — okumak uzun, işe yarar
```
